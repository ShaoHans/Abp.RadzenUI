# Lessons

- UI 扩展优先复用 Radzen 官方组件，只有组件无法承载时才补最小 CSS/JS。
- 用户明确要求 UI 调整不要新增 `.css` 文件时，优先用 Radzen 组件参数、布局参数和最小内联样式完成；先满足约束，再考虑局部样式文件。
- loading、登录页这类品牌入口优先复用 LoginPageSettings/TitleBarSettings，避免在 Razor 或 CSS 里写死图标和品牌素材。
- 不要因为当前编辑器停留在某个业务仓库就默认任务实现也在该仓库；如果用户明确点名 Abp-RadzenUI 这类目标项目，必须先锁定目标仓库，其他仓库只作为交互或实现参考。
- 公共库里的“类型”字段如果用户明确拒绝类型表，就不要继续沿着字典表/定义表设计推进；改用字符串字段 + 可 override 的选项提供接口，避免过度设计。
- 当消息正文可能是 HTML 时，设计阶段就要把它视为富文本展示需求，而不是默认按纯文本处理；后续实现必须同时考虑可渲染和安全边界。
- 富文本详情在暗黑模式下不能只设置容器背景；还要处理正文内部常见的白字/黑字/浅底内联样式，否则消息内容会在主题切换后局部不可见。
- 公共 Razor 组件不要硬编码某个布局专用的 class；一旦要在登录页、Header 等多个容器复用，应把样式类参数化或按宿主分别包裹，否则很容易退回到组件库默认外观。
- Radzen 组件一旦同时使用 `Template` 和子节点，优先改成显式 `Template=@...`、`ChildContent=@...` 参数传递；不要在组件体内混用条件块和匿名子内容，否则 Razor 很容易触发 `RZ9996`。
- 菜单 badge 这类动态装饰如果来源于 `IMenuItemDecorationContributor`，就不能只在侧边栏初始化时取一次；至少要绑定到路由变化或某个 scoped state 事件上，否则数字只会在整页刷新后更新。
- 公共库里的菜单 badge 刷新不要偷懒复用消息中心这类业务状态；应提供独立的 `MenuItemDecorationState`，并用刷新键让侧边栏只重算受影响的菜单项，避免一次消息已读把待办等无关查询也全部重跑。
- 数据库本地化覆盖走 ABP 的 `ILocalizationResourceContributor`（`IsDynamic=true`）而不是 `IExternalLocalizationStore`：后者要求返回抽象的 `LocalizationResourceBase`，开源框架里没有可直接 new 的非类型化具体资源。`LocalizationResourceContributorList.GetOrNull` 是**倒序**遍历（最后加入的先命中），`Fill` 是正序覆盖，所以把 DB 贡献器在 `IPostConfigureOptions<AbpLocalizationOptions>` 里 `Add` 到每个资源的**最后**，DB 值就会盖过静态 JSON。要读取“纯静态基准值”用 `resource.Contributors.Fill(culture, dict, includeDynamicContributors:false)`。
- ABP 的 `IStringLocalizer`/`IAuthorizationService` 扩展方法（如 `IsGrantedAsync`）定义在 `Microsoft.AspNetCore.Authorization` 命名空间下，不是 `Volo.Abp.Authorization`；`.razor.cs` 代码后置文件不吃 `_Imports.razor` 的 `@using`，缺了这个 using 会报“未包含 IsGrantedAsync 的定义”。
- Blazor CSS 隔离(`.razor.css` + `::deep`)只给 `.razor` 里的**原生 HTML 元素**打 `b-{hash}` scope 属性,不会打给 `<RadzenStack>` 这类子组件的根节点。所以 `::deep` 前缀若挂在 `<RadzenStack class="...">` 上,整份 scoped 规则会匹配不到任何元素、静默失效(表现为“改了没效果”)。要控制 Radzen 内部结构,更稳的做法是把规则写进 `wwwroot/css/site.css`(由 `BlazorGlobalStyleContributor` 全局加载),用一个包裹用的原生 `<div class="xxx">` 作用域类前缀 + Radzen 自带结构类(`.rz-tabview`/`.rz-tabview-left`/`.rz-tabview-panels`/`.rz-tree`),既不依赖 scope 属性,也不依赖组件是否透传 `class`。注意:无论 scoped 还是 site.css,Razor 标记改动都必须**重新 build + 重启** Blazor Server 宿主才生效,热重载不认。
- 嵌套 RadzenTabs + RadzenTree 想只保留“树内单滚动条”时:Radzen 默认 `.rz-tabview-panels{flex:1;overflow:auto}`、`.rz-tree{overflow:auto}` 都会各自出滚动条。正解是搭一条 flex 撑满链(每层 `min-height:0`,tab 面板 `overflow:hidden`,面板/子 tabview `height:100%`),把唯一滚动条交给树;直接删滚动条而不撑高会让整个 Dialog 变成滚动体,表头跟着滚走。链条根部必须是**确定高度**(`height:calc(...)` 而非只有 `max-height`),否则子层 `height:100%` 无法解析、树拿不到边界。
- 不要给 `.rz-tabview-panel` 直接加 `display:flex`:Radzen 用**内联 style** 切换未选中面板的显隐,内联会盖过你的类规则(选中面板可能被强行 block、未选中面板可能被你的 flex 顶开)。当一个 tab 面板里除了树还有别的元素(如“全选”复选框、分隔线),要让树独占滚动,应在面板内自己包一个 `display:flex;flex-direction:column;height:100%` 的原生 `<div>`,树设 `flex:1;min-height:0`;面板只给 `height:100%`。DialogFormLayout 的滚动体默认 `BodyStyle="flex:1;overflow:auto"`,复用它做单滚动布局时把 `BodyStyle` 覆写成 `display:flex;flex-direction:column;flex:1;min-height:0;overflow:hidden`,让内部 tabs 撑满、滚动条落到树上。
- ABP 开源版 `AbpSignInManager.PreSignInCheck` 有三条会直接返回 `SignInResult.NotAllowed`(登录页报 "IsNotAllowed"):`!user.IsActive`、`user.ShouldChangePasswordOnNextLogin == true`、`ShouldPeriodicallyChangePasswordAsync`(定期改密超期,用 `LastPasswordChangeTime ?? CreationTime` 判断)。其中 **`ShouldChangePasswordOnNextLogin`(“下次登录须改密”)是 Account **Pro** 商业版才有配套强制改密页的功能;开源版设成 true 会把用户永久挡在登录外、且没有任何改密入口**——所以管理端不要提供“下次登录须改密”开关。管理员设密应照 ABP 官方 `IdentityUserAppService.UpdateAsync` 的做法(`RemovePasswordAsync`+`AddPasswordAsync`),并额外 `user.SetShouldChangePasswordOnNextLogin(false)` 显式清除该标志,既符合“管理员刚设好密码”的语义,也能把之前误被置 true 而锁死的用户救回。
- `RadzenTabs TabPosition="Left"` 做“单滚动条撑满链”时,只处理右侧面板还不够:左侧导航 `.rz-tabview-nav` 会随 tab 数量把整个 tabview 撑高,权限组一多下面的组就被挤出可视区且不出滚动条。要给 `.rz-tabview` 补 `flex:1`(在弹窗 body 的 flex 列里填满剩余高度,让 tabview 有确定边界),并给 `.rz-tabview-nav` 加 `min-height:0;max-height:100%;overflow-y:auto`,左侧列表才会独立纵向滚动。
- 本地化贡献器的同步 `GetOrNull`/`Fill` 会被 `L["key"]` 高频调用，不能在里面查库：用单例 store 做 L1 内存快照（同步读）+ `IDistributedCache` 做 L2（跨节点），写操作即时失效本节点 L1、移除 L2，其他节点靠 stale-while-revalidate 在 `RefreshInterval` 内收敛。store 的后台/fire-and-forget 查库必须自建 scope + `IUnitOfWorkManager.Begin`，因为脱离了请求作用域。
- DataGrid 操作列改用 split button(主按钮带文字 + 下拉箭头)后，列宽必须按“图标 + 文案 + 箭头”的实际宽度给足：Radzen 主题里 `.rz-grid-table td .rz-cell-data` 是 `display:block;overflow:hidden`，内容超出列宽会从**尾部**被裁掉，而尾部正好是下拉箭头 —— 表现为“点不到那个箭头”。宽屏看不出问题，因为 DataGrid 会把剩余宽度分给各列把声明宽度撑大；只有窄屏落回声明宽度时才暴露。material-dark 下 Small 主按钮 `padding:0 1.375rem` + 图标 1rem + 箭头按钮约 1.75rem，加上单元格左右 padding，含中文两字文案的 split button 至少要 130px，所以角色/租户/用户三个列表统一取 150px。同理，凡是靠固定 px 列宽承载“带本地化文案的按钮”的地方，换语言(如德语 Bearbeiten)仍可能再次裁切，评估时按最长语种算。
- Radzen DataGrid 只要有列声明了 `Width`，表格就会带上 `.rz-grid-table-fixed{table-layout:fixed}` 且 `width:100%`，于是有两个方向的坑：①各列固定宽度之和**小于**容器时，多余宽度按比例摊给所有列，声明 150px 的操作列在宽屏会被撑到 190px+，按钮左对齐后右侧留出一大块空隙；②想靠“留一列不写宽度”吃掉剩余宽度（角色列表就是这么巧合地贴边的，它只有一个固定列），在固定列很多的表上会反过来出事——固定列之和**大于**容器时，自适应列拿到的剩余空间是 0，宽度归零，`overflow:hidden` 把表头和内容一起吃掉，那一列直接消失。所以列多的表不要用自适应列去修空隙，应该给操作列加 `TextAlign="TextAlign.Center"`（数据字典、本地化文本列表已是此做法）把按钮居中，让摊到的多余宽度变成对称留白。
- 给导出加样式配置时，MiniExcel 有两个静默的坑：①`EnableAutoWidth = true` 必须同时 `FastMode = true`，否则写入时抛 `Auto width requires fast mode to be enabled`；②`OpenXmlConfiguration.StyleOptions` 本身非 null，但 `StyleOptions.HeaderStyle` **默认是 null**（MiniExcel 内部再兜默认值），直接 `StyleOptions.HeaderStyle.WrapText = ...` 会 NRE；要自己 `new OpenXmlHeaderStyle()`——好在它的默认 `BackgroundColor` 就是 MiniExcel 那个表头蓝（A=40,R=68,G=114,B=196），所以只改 WrapText 不会把底色弄丢。另外 `configuration: null` 与 `new OpenXmlConfiguration()` 的产物等价（字节数相同），所以包装一层配置不会改变既有页面的输出；但 MiniExcel 1.44→1.45 自己改了默认列宽（13 → Excel 默认 8.43），升级依赖时导出文件观感会变。
- 用接口默认实现（C# 8 default interface member）保留过时重载时，只有**通过接口引用**才调得到；`new 具体实现类()` 再调旧签名会编译不过。所以这种“保持向后兼容”只覆盖注入接口的生产代码，直接 new 实现类的测试/工具代码仍需改。
- MiniExcel 的「单元格边框」和「表头底纹」是同一个开关 `TableStyles`（只有 None/Default 两个值）：Default 会给表头和每个数据单元格都套 thin 边框并给表头填 `#4472C4`(alpha 40)，None 则两者全没，做不到「无边框但表头有底色」。更坑的是 None 时 `StyleOptions.HeaderStyle` 会被引擎**完全忽略**（产物字节数与不设它时一致），所以对外暴露表头样式选项时必须让它隐含切到 Default，否则用户设了颜色却毫无反应。冻结窗格、自动筛选、列宽自适应不受这个开关影响。
- 邮件设置里的 SMTP「域」(`SmtpDomain`) 不能做成必填：ABP 的 `SmtpEmailSender` 只要域非空就构造 `NetworkCredential(user, pwd, domain)`，而 .NET 的 LOGIN 认证会把用户名拼成 `domain\user` 发给服务器，普通 SMTP 服务器必然认证失败；更隐蔽的是 `SmtpClient` 认证失败**不抛异常**、退化成匿名会话继续发，最终只在 RCPT 阶段报 `4.7.1 Relay access denied`，看起来像是服务器权限问题。域只用于 Windows/Exchange 的 NTLM，普通 SMTP 必须留空。
- ABP 的 `MapExtraPropertiesTo`（含 Mapperly 的 `[MapExtraProperties]` 默认 `DefinitionChecks = Null`）在源类型有属性定义、目标类型**完全没注册** `ObjectExtensionInfo` 时，默认会把该属性**静默丢弃**（除非源定义 `CheckPairDefinitionOnMapping = false`）。所以把 DTO 映射到自建的视图模型（如 `ProfileDto → PersonalInfoModel`）时扩展属性会“看起来有数据却映射不过去”，要显式 `DefinitionChecks = MappingPropertyDefinitionChecks.None` 并用 `IgnoredProperties` 排除不该走表单的字段（头像）。同理，渲染扩展属性的组件要把「定义来源类型」和「绑定对象类型」拆成两个参数（`DefinitionType` vs `TEntityType`），否则对视图模型取定义只会得到空列表。
- 身份用户扩展属性的「个人中心只读/可编辑」不能复用 ABP 的 `UI.EditModal.IsReadOnly`，那是管理员编辑弹窗的语义；要给个人中心单独一维配置（`ProfileExtensionPropertyMode`），存进 ABP 自带的 `Configuration` 字典就能随模块扩展配置自动复制到各 DTO，且 UI 只读必须配服务端兜底（替换 `ProfileAppService`），因为 `ProfileAppService.UpdateAsync` 会无条件 `MapExtraPropertiesTo(user)`。
- ABP 模块级扩展（`ConfigureIdentity().ConfigureUser()`）复制到各 DTO 的 `ObjectExtensionPropertyInfo` 时，只带过去 `UI.Order`、`CreateModal` / `EditModal` 的 `IsVisible` / `IsReadOnly`、`Lookup`、`Policy`、`Attributes`、`DisplayName`、`DefaultValue` 和 `Configuration` 字典；**`UI.OnTable.IsVisible` 不会被复制**，DTO 级属性信息上根本没有「表格可见」这个概念。所以列表页想尊重 `OnTable.IsVisible`，必须拿模块名 + 实体名回 `ObjectExtensionManager.Instance.Modules()` 查模块级配置（`EntityExtensionConfiguration.Properties` 是 protected，用 `GetProperties()`）。另外 `ModuleExtensionConfigurationDictionary.ConfigureModule<T>` 是泛型扩展方法，直接用时要显式写 `<ModuleExtensionConfiguration>`，否则推断不出 `T`。
- 示例工程的「同一属性在多个 DTO 上各写一遍」是 ABP 按 DTO 定义 API 的固有形态；要只写一遍就走模块级扩展，但要先想清楚副作用：它会把字段同时加到管理员编辑弹窗（`Required` 会卡住老数据）和列表列上，需要用 `UI.OnEditForm` / `UI.OnTable` 显式收口。
- ABP 的 `MapExtraPropertiesTo` 在复制每个扩展属性时都会走 `SetProperty(validate: true)` → `ExtensibleObjectValidator.CheckValue`，所以给 Update DTO 定义了 `[Required]` 的扩展属性后，**打开编辑弹窗把 Get DTO 映射成 Update DTO 这一步就会抛 `AbpValidationException`**（老数据为空），表现为列表点「编辑」直接报内部服务器错误。加载表单不该校验，要自己按 `ExtensibleObjectMapper.CanMapProperty` 过滤后 `SetProperty(validate: false)` 复制。同样的 `[Required]` 还会被复制到 `UpdateProfileDto`，用户在个人中心填不了只读字段却要过服务端 DTO 校验，所以启动时要把非 Editable 属性在 `UpdateProfileDto` 上的校验属性去掉（保留 `DataTypeAttribute`，它决定输入控件类型）。
- ABP `CanMapProperty` 的语义要靠测试对照而不是靠记忆：当**源类型注册过** `ObjectExtensionInfo` 时，两边都没定义的属性也**不会**被映射（只有源类型完全没注册时才「自由映射」）。写这类辅助方法的测试时，直接拿 ABP 的 `MapExtraPropertiesTo` 结果做基准比较，别硬编码期望。
